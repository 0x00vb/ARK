# Local application bridge

ARK Inference provides ark-inference-bridge. ARK's ark-model crate provides Inference and InferenceConfig.
The engine runs as a persistent local child process. The bridge opens no network listener and downloads no model.
This first bridge supports text conversations only. Tool definitions, tool history, tool results, and pictures fail before process startup.
An agent call that requires tools receives a permanent capability error. It does not retry or silently discard tools.

It is a text-only transport proof, not a backend for agent work yet.

| Limit | Measured on an M4 Pro, Qwen3 4B Q4_K_M, 2026-10-16 |
|---|---|
| Tools | Refused before the child starts |
| Prefill | About 32 tokens/s on Metal. On CPU, 9 tokens/s with 8 threads and 2.5 tokens/s with the default 2 threads (448-token prompt, a busy machine) |
| Decode | About 8.5 tokens/s on Metal, 5.8 tokens/s on CPU with 8 threads |
| Prompt reuse | None. Every call re-runs the full prefill for the whole conversation |

`inference` is a reserved provider name. A named endpoint called `inference` is rejected.
Like any built-in provider, `/model inference /absolute/model.gguf` selects it in a chat. A path with spaces does not work in that form.

| Also know | Why |
|---|---|
| The Harness context budget is at least 1024 tokens | The default window is 480. Raise `ARK_INFERENCE_CONTEXT` for Harness use. On CPU, raise the prefill and call deadlines with it |
| Each provider loads its own model | `ARK_PROVIDER_FAST` and `ARK_PROVIDER_STRONG` set to `inference` load two copies |
| One active call per provider | Agents sharing one provider get a permanent error on a concurrent call |
| A cached child that exited while idle | The next call starts a new one instead of failing. A child that exits during a call still fails that call once |

## Build and select

Run these commands from the engine checkout.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 4
```

Enable ARK_METAL for an optional Metal build. Explicit metal selection fails when unavailable.
Configure ARK with absolute local paths.

| Setting | Meaning | Default |
|---|---|---|
| ARK_PROVIDER | Select inference | Explicit selection required |
| ARK_MODEL | Absolute local GGUF path | Required |
| ARK_INFERENCE_EXECUTABLE | Absolute bridge executable path | Required |
| ARK_INFERENCE_BACKEND | cpu or metal | cpu |
| ARK_INFERENCE_CONTEXT | Total token capacity | 512 |
| ARK_INFERENCE_OUTPUT_TOKENS | Reserved maximum generated tokens | 32 |
| ARK_INFERENCE_ARRAY_BYTES | Successfully retained request-array byte limit | 536870912 |
| ARK_INFERENCE_FILE_BYTES | Model file byte limit before mapping or reading | 17179869184 |
| ARK_INFERENCE_INPUT_BYTES | Serialized conversation payload byte limit | 1048576 |
| ARK_INFERENCE_OUTPUT_BYTES | Aggregate generated byte limit | 8388608 |
| ARK_INFERENCE_BATCH | Prompt batch capacity | 32 |
| ARK_INFERENCE_THREADS | CPU computation threads | 2 |
| ARK_INFERENCE_STARTUP_SECONDS | Deadline for the model to load | 120 |
| ARK_INFERENCE_PREFILL_SECONDS | Deadline from the request to the first token, which covers the whole prefill | 600 |
| ARK_INFERENCE_PROGRESS_SECONDS | Deadline for each frame after the first token | 120 |
| ARK_INFERENCE_CALL_SECONDS | Deadline for the whole call: model load, prefill and output | 600 |

InferenceConfig sets the same four deadlines. Zero deadlines fail configuration.
The prefill happens before the first token frame, so it has its own deadline.
A full 480-token window took about 3 minutes on CPU with 2 threads, measured while other builds shared the machine.
A larger context on CPU needs longer prefill and call deadlines too.
The input context reported to ARK subtracts reserved output tokens.
Configuration does not load weights. Only an actual completion starts the child.
The bridge has no automatic catalog scan or alternate backend fallback.

## Streaming and cancellation

Call Provider complete_streaming with a fast TextSink callback.
The adapter preserves token bytes across frames and emits only complete UTF-8 prefixes.
Incomplete or invalid final UTF-8 fails. It does not use replacement characters.
A later error can follow visible text. Such text is provisional and does not imply successful completion.
The returned Completion contains the full checked text and measured token counts.

Successful calls reuse the loaded model. They destroy request arrays and release backend registrations and staging before terminal success.
Compiled pipelines and immutable loaded model storage remain until provider destruction or cancellation.
The terminal frame reports remaining staging bytes and registration count. Both must equal zero before reuse.

Drop the completion future to cancel. ARK's Harness already drops its provider future when its CancelToken fires.
The adapter kills and evicts its owned child during startup, writes, prefill, streaming, or terminal waits.
Later calls start cleanly. Cancellation therefore requires another model load.
Dropping an idle provider also kills its cached child. Tokio performs child reaping.
One provider accepts one active request. Concurrent calls fail immediately without accumulating a waiting queue.
The child uses pipe backpressure. The adapter has no unbounded token channel.
The application must keep TextSink fast. A blocking callback cannot be preempted by an asynchronous timeout.

## Memory boundaries

| Bound | Includes | Excludes |
|---|---|---|
| File bytes | Model file size before mapping or reading | Residency and parsed metadata allocation |
| Array bytes | Actual KV, scalar scratch, and batch scratch vector capacities | Transient allocator excess and model/backend storage |
| Context | Prompt tokens plus reserved output capacity | Tokenizer temporary work |
| Input bytes | Serialized message count, role tags, lengths, and text | Caller-owned conversation and allocator overhead |
| Output bytes | Generated byte payloads before UTF-8 reconstruction | Allocator capacity, transport buffers, and caller copies |
| Frame bytes | At most 1048576 payload bytes before frame allocation | Pipe buffers and process metadata |

These bounds do not enforce total process RAM or GPU residency.
Model metadata, tokenizer storage, normalization vectors, thread stacks, allocator overhead, compiled pipelines, and device resources retain ADR 0010 scopes.
A hard process limit needs operating-system enforcement. This bridge does not install a sandbox or job limit.
The bridge releases input buffers before terminal output. Deallocation does not promise forensic erasure of allocator or operating-system copies.
Hard cancellation terminates the process. It does not run C++ destructors or promise forensic erasure.

## Protocol and compatibility

See [ADR 0073](adr/0073-local-inference-process-bridge.md) for the exact version-one byte format and state transitions.
Version mismatch, unknown frames, invalid lengths, invalid ordering, inconsistent counts, and nonzero cleanup reports evict the child.
Errors use fixed public codes. Prompt text and model paths do not enter automatic error details.
Child stderr goes to the null destination. It cannot block generation or forward private diagnostics into app logs.
The adapter clears the child environment. Windows retains SystemRoot for system-library loading.
Executable and model paths are explicit and absolute. Arguments never pass through a shell.

The transport has no C++ ABI dependency. ARK and the engine build independently.
Do not pin a consumer to this unreleased ARK worktree.
Release and consumer pinning remain separate owner-authorized work.
Windows and NVIDIA remain unexecuted until their own native evidence exists.

The companion engine procedure lives in ../ark-inference/docs/BRIDGE.md.
The runnable ark-model example local_inference reads its prompt from stdin and streams through the real Provider adapter.
A real run on 2026-10-16 (Metal, the Qwen3 4B file above):

```text
$ echo "What is 2 + 2? Answer briefly." | cargo run -p ark-model --example local_inference -- <bridge> <model.gguf> metal
2 + 2 = 4.prompt_tokens=19 output_tokens=8
```

The answer goes to stdout and the token counts to stderr, so they share a line in a terminal.
